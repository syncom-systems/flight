# Flight v1.0.1 release decision packet

Prepared 2026-10-13 for the owner. The release is a **draft** and is **not published**; nothing here publishes it. Purpose of 1.0.1: installation, documentation, diagnostics and qualification automation for the released 1.0.0. No new features and no architecture changes (milestone `v1.0.1`: #115, #116, #117, #118).

## Recommendation: GO

Every item of the milestone is done and verified on the stable packages; no known defect. Publishing the draft is the owner's decision. After publishing, one step remains: update the Homebrew formula (below), because it points at published assets.

## What changed since 1.0.0

Source: two error messages (#117: tmux missing or too old, agent program not found, now say what to do). Packaged documents: README rewritten as a quick start; `docs/{install,two-machines,services,concepts,troubleshooting}.md` (#115). Not in the package: Homebrew tap `syncom-systems/homebrew-flight` (#116) and the qualification automation (#118).

`Formula/flight.rb` in `syncom-systems/homebrew-flight` still installs 1.0.0. After publication: change its two URLs and `sha256` values to those above (from `SHA256SUMS`) in a pull request there; its workflow installs, audits and tests it. No credential links the repositories.

## Risks that remain

1. The documentation is better but a person has not yet followed it cold; the first outside user will. Feedback goes to issues.
2. Real hardware: the owner's two-machine and launchd checks were run on 1.0.0-rc.1; for 1.0.1 the same flows are covered by the scripted checks above, not repeated by hand.
3. Setup still needs a terminal; the installer experience (setup screen, dependency installs, agent choice, a signed Mac app) is milestone `v1.1.0` (#119-#121), not part of this release.
4. Immutability of the published release is shown at publication (as for 1.0.0).
