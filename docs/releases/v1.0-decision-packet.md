Prepared 2026-10-11 for the owner. The stable release is **not** published; nothing here publishes it.

No engineering blocker remains. ## Supported platforms (contract section 3)

macOS on Apple silicon; Linux x86_64, glibc 2.36 or newer (built on Debian 12); tmux 3.3 or newer, enforced. Unsupported and listed: Windows, Linux arm64, musl, macOS Intel, tmux older than 3.3 (Ubuntu 22.04 and Debian 11 distribution tmux), public-internet exposure of the orchestrator.

## Qualification evidence

Full matrix with sources: `v1.0-readiness.md`. In short, all on the rc.1 packages, not source builds:

- Clean install and first run, journey (create, shells, name, quit and return, tmux lost, one restore): bare Debian 12 container and fresh macOS runner (Qualify run 38156875152), and the maintainer's Mac.
- Distributed: separate enrolled orchestrator, node and dashboard; reused and expired bundles refused; node and orchestrator killed and restarted; revocation (same run, same machines).
- Upgrade and rollback with the real pre-1.0 binary: carried over, schema 2, backup kept, old binary refuses the newer file untouched, backup restores (same run, Mac).
- systemd user services on a fresh Ubuntu runner (run 38159656430): install per `docs/install.md`, kill -9 restarts, stop/restart keep the sessions, uninstall keeps data.
- tmux versions: Qualify run 38150791711.

Defects found by this process and fixed before the candidate: saved files silently dropping keys an older build did not know (#84); restore bringing back only the first shell (#98); tmux older than 3.3 failing (#86, enforced).

## Known limitations (do not block)

Issue #91, notably: tmux older than 3.3 unsupported; config directory path limited by the Unix socket length (about 90 characters); shells are chosen and named only from the dashboard; only agent and shell surfaces; mouse selection in multi-tile presentations needs the terminal's shift key; `serial` advisory above.

## Upgrade and rollback

`docs/install.md` ("Backup", "Upgrade", "Roll back"). Back up `~/.config/flight`, replace the binary, restart services. Saved files upgrade in place and the original is kept as `workspaces.v<N>.bak`. A newer file is never read by an older Flight; roll back by restoring the backup.

## Milestone status

Milestone `v1.0.0`: blockers and qualification tasks #82-#90, #98 closed with evidence; open: #108 (owner-run). #91 (known limitations) and #92 (post-v1 backlog) are not in scope of the release.

## Unresolved risks

1. No run on separate physical machines with this candidate (#108); the last such run predates the workspace and presentation work.
2. launchd service not re-verified on this candidate (#108).
3. The real Claude CLI is not exercised by the release qualification (a stand-in program is), only by tests with a fake that behaves as the real one (#108).
4. Publication-time immutability of the release (repository setting) cannot be demonstrated before publishing.
5. The stable tag changes the bytes; Qualify must be re-run on the stable packages.
6. Mixed-version compatibility inside 1.x is by design and simulation only; there is no earlier 1.x release to test against.
