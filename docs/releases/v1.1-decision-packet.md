## What 1.1.0 adds

- **Guided setup** (ADR-012): `flight setup`, and a once-only offer from a plain `flight` on a terminal when tmux or every agent program is missing. Each command is shown first and runs only after an explicit yes; success is checked by looking; Homebrew itself is never installed; `--check` runs nothing; `--no-setup` and `FLIGHT_NO_SETUP=1` turn the offer off; without a terminal nothing is asked or run (as in 1.x). Preferences are saved in a versioned, private `settings.toml`.
- **Agent providers** (ADR-013): the launch path is behind a provider interface; **Codex** is a workspace agent next to Claude, for people who chose it in setup. Wire: additive program codes and the capability `agent_codex_v1`; Claude's codes are unchanged; an older node is refused cleanly ("too old"), never started wrongly. A restored Codex workspace is a new conversation and says so (Codex does not let Flight identify its conversation).
- Fixes found on the way: a latent race in a test scaffold, the apt path of setup (update then install, no sudo as root).

## Risks that remain

1. Codex is verified with a real CLI on macOS arm64 and one CLI version; Codex's own behaviour can change between its releases. The suite uses its own stand-in elsewhere.
2. Guided setup has run on a bare Debian 12 (apt, as root) and in tests with a recording `brew`; it has not been run against a real, empty Homebrew installation on a clean Mac (the Homebrew commands are the documented ones, checked with `brew info`).
3. People who do not use a terminal are still not served (#121, deferred by decision).
4. Immutability of the published release: confirmed after publication (`immutable: true`).
